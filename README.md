# algo-prog-course
ПР1. Ответы на контрольные вопросы
1.там программа выполняется построчно
специальной программой-интерпретатором: она читает строку, тут же её выполняет,
читает следующую.
C# устроен иначе. Прежде чем что-то запустить, специальная программа —
компилятор — читает весь исходный код (.cs файлы) и переводит его в
промежуточный машинно-независимый код, который затем выполняет среда .NET.
2.Собирает проект (компилирует .cs файлы) — эта стадия называется build.
Запускает получившуюся программу.
3.bin/ Сюда компилятор кладёт скомпилированную программу
(результат сборки).
obj/ Служебные промежуточныефайлы сборки.
4.git commit -m "Описание" Сохранить снимок (коммит) с сообщением
git push Отправить снимок на GitHub
5.Конкатенация (+): Склеивает строки последовательно. Интерполяция ($"..."): Позволяет вставлять переменные и выражения прямо внутрь строки в фигурных скобках. Код становится гораздо более читаемым и компактным (нет кучи плюсов и кавычек). 
6.Если оба операнда — int, результат деления тоже будет int, а
дробная часть просто отбрасывается (не округляется!). Чтобы получить точный
результат, нужно превратить хотя бы один операнд в double — это делается через
(double) перед переменной, это называется явное приведение типов (explicit cast).
7.top-level statements —начиная с C# 9, для простой программыне
нужно писать class Program { static void Main() { ... } } вручную, компилятор достраивает
всё сам.
ПР2. Ответы на контрольные
вопросы
1.double хранит число в
двоичном виде, и некоторые "простые" на вид десятичные дроби (например, 0.1) не
могут быть представлены в двоичной системе абсолютно точно — накапливается
крошечная погрешность. Для физических расчётов это не страшно, но при работе с
деньгами копейка расхождения — уже баг. decimal устроен так, что подобных проблем
не возникает.
2.Счетчик просто сбросится на противоположный конец диапазона без генерации ошибки.
3.var — это не аналог динамической типизации Python. Тип всё равно
определяется один раз, во время компиляции, просто вы не пишете его руками —
компилятор смотрит на то, что справа от =, и подставляет тип сам. После объявления
var age = 20; переменная age — это самый обычный int, и присвоить ей потом строку
так же нельзя, как обычной int-переменной
4.Console.ReadLine() всегда возвращает string, даже если пользователь ввёл число.
Если нужно число — строку придётся преобразовать.
5.int.Parse То же самое — бросит FormatException
int.TryParse Не упадёт. Вернёт false в переменную ok, а в c запишет 0
6.Возвращенное значение `false` означает, что входную строку не удалось преобразовать в целое число
7.Считывание возраста пользователя, вводимого в консоль или форму.
никак нельзя контролировать, что именно введет живой пользователь. Человек может случайно нажать не ту клавишу, написать число словами или оставить поле пустым.
