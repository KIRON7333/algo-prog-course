# algo-prog-course
ПР2. Ответы на контрольные
вопросы
1.double хранит число в
двоичном виде, и некоторые "простые" на вид десятичные дроби (например, 0.1) не
могут быть представлены в двоичной системе абсолютно точно — накапливается
крошечная погрешность. Для физических расчётов это не страшно, но при работе с
деньгами копейка расхождения — уже баг. decimal устроен так, что подобных проблем
не возникает.
2.Счетчик просто сбросится на противоположный конец диапазона без генерации ошибки.
3.var — это не аналог динамической типизации Python. Тип всё равно
определяется один раз, во время компиляции, просто вы не пишете его руками —
компилятор смотрит на то, что справа от =, и подставляет тип сам. После объявления
var age = 20; переменная age — это самый обычный int, и присвоить ей потом строку
так же нельзя, как обычной int-переменной
4.Console.ReadLine() всегда возвращает string, даже если пользователь ввёл число.
Если нужно число — строку придётся преобразовать.
5.int.Parse То же самое — бросит FormatException
int.TryParse Не упадёт. Вернёт false в переменную ok, а в c запишет 0
6.Возвращенное значение `false` означает, что входную строку не удалось преобразовать в целое число
7.Считывание возраста пользователя, вводимого в консоль или форму.
никак нельзя контролировать, что именно введет живой пользователь. Человек может случайно нажать не ту клавишу, написать число словами или оставить поле пустым.
